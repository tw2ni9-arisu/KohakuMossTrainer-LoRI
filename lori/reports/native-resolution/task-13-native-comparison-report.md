# Task 13：原生分辨率 90% 稀疏（250/550/850/900）与 Base、256² 稠密参考的对比

**结论先行。** 原生分辨率（约 1.02 MP）训练的 90% 移除稀疏 LoRI，取 250/550/850/900 四个检查点，与 Base、稠密 900@256² 参考在同一 12 行、同一采样配方下渲染成 6 列网格（新渲染 48 张，Base 与参考只读复用）。

1. **起点与采样路径可信。** 4 份导出逐份通过：252 层、`b_values` 1,066,599 全非零、`active_indices` 与 task11 的 90% 掩码逐层逐位一致、`a_sha256 = 976522f0…`、A/alpha 504/504 为 canonical、comfy 导出为 `inference_only_dense_b`；canary 重放 task10 稠密 285/570 的 r00/r14 **4/4 位级相同**，说明训练器工作树改动没有影响采样数值路径。
2. **与 Base 的距离先升后平。** 12 行均值：N250 **16.16** → N550 23.26 → N850 26.45 → N900 26.07；四个原生列都小于稠密 900@256² 参考的 33.60。**250 是最接近 Base 的一列**（构图、配色几乎不变），550 起明显向稠密参考的画风靠拢。
3. **步进量前大后小。** 250→550 **18.00**、550→850 14.46、850→900 只有 **6.09**（最后 50 步基本收敛）、250→900 21.61。
4. **与 256² 稠密参考的距离随步数单调下降**：32.30 → 29.88 → 28.12 → 28.04。原生模型越训越接近 256² 稠密 900 的观感，但四列都没有重合。
5. **尺度不匹配是首要限制。** 训练在约 1.02 MP、采样固定 512²；Native 列与 Base/参考的所有像素差都同时包含"训练分辨率 + 采样尺度"的差异，**不能**读成稀疏度或步数的纯效应。
6. **质量观察（8 张 512² 原图）**：原生四列都没有出现 256² 稠密 900 那种空白脸/转脸；N250、N550 的面部与手部最干净，N900 的服装细节更碎（r00 的缎带与领口条纹结块），但面部仍可读。**像素差不是质量排名。**

实际打开 8 张 512² 原图（r00_c02、r00_c05、r04_c02、r04_c05、r08_c02、r08_c05、r03_c04、r11_c03）与 6 列总览/分组 sheet：

- **N250（c02）**：12 行都与 Base 同构图同配色，最明显的差别是**布偶/主体被放大**（r00 的布偶明显大于 Base，r02 的布偶脸更大），属于构图尺度漂移；面部完整（r00_c02、r04_c02、r08_c02 的眼、嘴、手指都可读）。
- **N550（c03）**：布偶缩回正常比例，发色与服装开始向稠密参考靠拢；r11_c03 的两位人物换成棕发/深发与青绿、深蓝裙（提示未指定发色，属提示范围内的重新采样）。
- **N850 / N900（c04/c05）**：整体画风向 256² 稠密 900 靠近（发色变深、肤色转冷、服装更"层叠"），r00_c05 的缎带与领口条纹出现轻微结块，但**面部仍然可读**；r03_c04 的两位人物面部干净，没有 task10 稠密 900 的 r03 那种崩坏。
- **没有出现** task10 稠密 900 的空白脸/转脸（r00、r08 的同类形态在本轮四个原生列里都没有复现），这是本轮最值得记录的定性差异；但它也可能是 512² 采样把 1.02 MP 训练学到的高频细节"压平"后的结果，不能直接读成"原生训练更稳"。

- **canary（GPU）** exit 0，354.5 s（渲染 333.9 s），4 张；CUDA 峰值 allocated 2,120,034,816 B（1.97 GiB）/ reserved 2,181,038,080 B（2.03 GiB）。
- **generate（GPU）** exit 0，**3,412.3 s（56.9 分钟）**，48 张（4 列 × 12 行，单进程一次加载 DiT，每列约 850 s）；CUDA 峰值 allocated 2,120,034,816 B / reserved 2,193,620,992 B（2.04 GiB）。

- **训练侧事实（引用，未在此重算）**：900 步训练调用 5,613.6 s（约 1.56 h），平均 6.10 s/步；loss 均值 0.37517（**原生分辨率尺度，与 256² 的 0.70493 不可直接比较**）；B 全局 L2 250→900 为 2.105 → 3.326 → 4.308 → 4.398；优化器 252 entry、两列矩各 1,066,599（合计 2,133,198）。
- **过程异常**：① 本任务 canary 第一次失败（launcher 对 canary 也设了 `CUDA_VISIBLE_DEVICES=-1`，driver 报 "No CUDA GPUs are available"），已修 launcher 并以 `stages/canary-attempt1` 保留失败证据，第二次 4/4 通过；② 训练侧 cache 首次因审计统计写错 exit 1（三个 native pass 本身成功，recheck 通过）；③ seg550 首次因"构建期 B 非零"的错误断言 exit 1（未跑步），修正后同配置 RESUME 成功；④ 训练侧两次 freeze amendment（run.py）；⑤ step 251/551/851 的 step_time 0.02–0.05 s 是恢复阶段计时归属伪影，900 行连续、无跳步。

## 9. 限制

1. **尺度不匹配**：训练约 1.02 MP，采样固定 512²；Native 列是在训练分辨率一半线性尺寸上采样，与 256² 训练的参考、以及与 Base 的比较都受尺度影响。Native 四列之间可比（同配方同分辨率），与 c01 的对比不是同训练分辨率对比。
2. **掩码来自 256² 校准**：90% 掩码是 task11 在 256² 校准阶段选出的，直接用于原生分辨率训练；掩码本身不随分辨率重新校准。
3. **无留出集**：全部训练图都参与训练；900 步约 3.16 个数据轮次（按 task11 的 285 张计），只有一条 seed 轨迹。
4. **无真人盲评**：视觉结论来自单人观察 8 张原图与 6 列缩略，未做盲评打分。
5. **像素差不是质量排名**：r00/r03 这类行本身方差大，列内标准差 4.5–9.9 与列间差同量级。
6. **步进量的解释有限**：250→550 的最大跳变与"第一段训练 + 恢复点"重合，无法与纯优化动力学区分。
