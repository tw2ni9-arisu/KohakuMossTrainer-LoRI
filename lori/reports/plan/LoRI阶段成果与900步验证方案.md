# MOSS-Image DiT LoRI 阶段成果与 900 步验证方案

更新日期为 2026-11-18。本文件汇总当前实现和实验记录，并规划下一轮使用全部标注数据的稠密 B 训练。方案已于 2026-11-18 执行完毕：实际数字、产物入口与三条边界见文末[执行结果（2026-11-18）](#执行结果2026-11-18)；对照与复核见 [三列对照报告](docs/execution/dit-lori/task-10-comparison-report.md) 与 [独立复核](docs/execution/dit-lori/task-10-independent-review.md)。

## 阶段成果

### 实现与工程验证

- 在工作区内的 KohakuMossTrainer 副本上加入 MOSS-Image DiT LoRI，保留训练器的 INT8 主干、BF16、层流送、激活与梯度卸载、主机优化器状态等低显存路径。源目录 `D:\Develop\nigenmame-LoRA` 保持只读。
- KohakuMossTrainer 和 MOSS-Image DiT、Qwen 文本编码器、VAE 权重优先复用了 `D:\Develop\nigenmame-LoRA` 中的本地文件，副本均保存在当前工作区。
- LoRI 使用冻结的随机投影 A 和可训练 B。稀疏阶段以全目标层 `abs(B)` 的统一阈值生成掩码，清零 B 后只保存并训练活跃坐标。优化器状态按活跃坐标紧凑分配，前向仍会暂时重建稠密 B，因此没有声称稀疏 FLOPs 或总显存同比例下降。
- 真实 MOSS-Image 主干的训练和原生推理路径已用于首轮实验。实现审查记录为 256 项通过、56 项跳过。独立导出不再依赖原掩码文件，并用真实训练权重在 CPU 上重导核验。
- 根目录论文复核发现 Knit-Edit 是视觉 DiT 上的相关先例，但它使用 FLUX.1 Kontext、编辑条件和 6,000 对数据，主实验为 rank 8、零稀疏率、3,000 步。它支持“视觉 DiT 可用类似思路”这一方向，不证明 MOSS-Image 上的 90% 稀疏或 900 步效果。

### 已完成训练

首轮使用指定目录中确定性选出的 12 对图文，目标面积 256²，rank 8、alpha 16、`attn-mlp` 共 252 个目标模块、seed 42、AdamW 学习率 `1e-4`、恒定调度、INT8 主干与 BF16 训练。

| 阶段 | 实测结果 |
| --- | --- |
| LoRI 校准 | 稠密 B 校准 12 步，252 个 B 更新，A 与 alpha 保持不变 |
| 90% 稀疏掩码 | 全局保留 1,066,599 / 10,665,984 个 B 值，约 10%；阈值并列按 `>=` 保留 |
| 稀疏训练 | step 32 续训到 step 232；252 个紧凑 B 均更新，AdamW 两组矩共 2,133,198 个元素 |
| 稠密 B 对照 | 新优化器从零训练 232 步；252 个稠密 B 均更新，可训练 B 值 10,665,984 个 |
| PyTorch 峰值 | 稀疏 2.40 / 2.69 GiB，稠密 2.43 / 2.72 GiB，分别为 allocated / reserved；差约 34 MiB |
| 训练平均 loss | 稀疏 232 步为 0.72289，稠密 232 步为 0.71226；两者均反复使用同 12 张训练图，不能据此判断图像质量或泛化 |

稀疏和稠密两组使用同一批 12 张图、相同固定 A、同一数据顺序与采样随机流。稠密训练 232 步的最终 B 更新范数高于稀疏组，逐层比值中位数为 2.60。这是参数更新幅度，不是质量排名。

### 图像比较

当前已完成 32 与 232 步稀疏结果比较，并完成 step 232 的稠密、稀疏及 Base 三列比较。最新一轮包含 3 个场景、每个场景带词和不带词的提示，共 18 张 512² 图，使用相同种子、Euler 50 步、CFG 3、shift 5 和 two-pass CFG。

稠密组相对 Base 的六行平均 RGB MAE 为 34.93，稀疏组为 28.81，六行里稠密组都造成了更大像素偏移。星空组出现较明显的眼部高光、发丝和衣褶变化，粉色双人和海边组也出现服饰或构图变化。触发词影响方向不一致，既没有证明风格质量更好，也没有证明触发词稳定控制风格。RGB MAE 仅描述像素偏移。

现有图像组的提示与训练参照主题接近，场景和种子覆盖有限。全部 285 条原始 caption 均以 `nigenmame` 开头，训练时 `TEXT_DROP=0`，因此当前数据也不能单独验证模型是否学会了触发词与风格之间的关联。

## 下一轮使用全量数据的 900 步训练

### 实验目的与边界

本轮测试扩大到全量 285 对图文后，固定 A 的稠密 B 是否能在 900 次有效更新内产生可重复的视觉变化。它不是旧 12 图实验的纯步数对照，因为训练数据池扩大了。为了得到本轮内部可比的学习轨迹，在同一新 run 中保留 step 285 和 step 900 检查点，比较两者并同时看 Base。

### 数据与训练配方

原始目录已经只读盘点，共 285 张图像（279 PNG、6 JPG）和 285 个同名 caption。285 组文件名均一一对应，caption 均非空。每条 caption 都包含 `nigenmame`。启动前仍需用实际训练分词器检查缓存数、超长过滤和训练 loader 行数，确保没有样本被静默丢弃。

| 项目 | 方案 |
| --- | --- |
| 训练集 | `D:\Develop\nigenmame-LoRA\dataset-raw\round2-caption` 内全部 285 对图文；图像和 caption 只读引用，不移动、不删除、不复制进模型目录 |
| 数据工件 | 在当前工作区生成独立清单与离线 latent/text cache；保存文件清单、caption 与图像哈希、缓存计数及解析配置 |
| 训练方式 | 新 run，从零初始化 B 和 AdamW；不恢复 12 图训练的 optimizer、数据游标或 RNG。使用 seed 42，并在启动审计中比对 A/alpha 哈希 |
| LoRI 形态 | 固定 A、稠密 B，不生成稀疏掩码；rank 8、alpha 16、`attn-mlp` 252 个目标 |
| 其余配方 | 256² 目标面积、batch 1、梯度累积 1、INT8 ConvRot 主干、BF16、AdamW `1e-4`、零权重衰减、恒定学习率、现有 `ckpt-ring4-actoff-optstream-gradoff` 配置 |
| 更新数 | 总计 900 次有效更新。若全部样本均被 loader 接受且 batch 为 1，约为 3.16 个数据集轮次 |
| 检查点 | `SAVE_EVERY=285`、`KEEP_LAST=4`，保留 step 285、570、855 和最终 step 900；新输出放在 `experiment/task10/session-20261118-a/` |

使用全量数据后必须重新缓存，不能沿用只含 12 张图的缓存，也不能从旧 dense232 checkpoint 续训。后者的 optimizer 历史和数据游标来自不同的数据池。全量 run 的 step 285 与 step 900 才是同配方的训练进度比较。若 seed 42 初始化出的 A 与旧 dense232 不同，记录差异即可，不更换训练数据或强行恢复旧 checkpoint。

### 图像评估

准备 6 个内容不同的提示组，其中 3 个用于衔接现有粉色双人、星空和海边锚点，另 3 个采用与原 caption 不同的场景组合。每组使用 seed 42 和 43；每个 seed 做只差 `nigenmame, ` 前缀的有词/无词提示。总计 24 行。每行在同一网格比较 Base、step 285 稠密 B 和 step 900 稠密 B，共 72 张图。

沿用 512²、Euler 50 步、CFG 3、shift 5、two-pass CFG、batch 1、BF16、INT8 Base 和 `minimal` 显存档。检查新网格中固定 Base 与旧锚点的解码 RGB 哈希，确保采样条件没有漂移。当前 `compare_grid.py` 支持 Base 加多份 checkpoint 列。

评估时隐藏模型列名，分别记录目标画风线索、提示内容遵循和结构/绘制瑕疵。成对比较带词和无词结果时，同时扣除 Base 对同一词语本身的响应。训练损失和 RGB MAE 作为辅助记录，不用作风格质量判据。

由于全部 285 张图都参加训练，本轮没有独立图像留出集。新增提示只提供定性组合测试，不能据此声称严格的泛化能力或触发词因果效果。若要回答这些问题，后续需获得训练目录之外的独立参考集，或另开保留验证集的实验。

### 完成判据与后续分支

- **训练完整性**：实际 worker 与启动器正常退出；状态到 step 900；无跳步和非有限更新；caption、latent 与 loader 记录覆盖全部 285 条；252 个 B 都有更新；A/alpha 不变；step 285 与 900 检查点和导出可读。
- **视觉信号**：预先按盲评表比较 step 285 与 900。只有当大多数场景、两个种子下的风格评分方向一致，且提示遵循与结构质量没有重复退化时，才记录为小样本视觉增益。单张图变化或 MAE 增大不满足此条件。
- **过拟合边界**：全量数据的 900 步约 3.16 轮，与旧 12 图的 232 步和 900 步约 75 轮的重复程度不同。训练损失变低不等于验证改善，现有数据全用于训练，过拟合仍需靠后续独立数据确认。
- **值得接着验证的方向**：若稠密 step 900 有明确视觉信号，再用同一 285 图配方训练稀疏 LoRI 到 900 步，才能比较稀疏与稠密的同预算质量；之后再做普通 LoRA 同预算基线、稀疏率/校准步数消融，以及独立留出评估。Knit-Edit 的 3,000 步不能直接当作本模型的推荐训练长度。

全量文本缓存可能占据主要准备时间。历史上 13 条文本 embedding 的缓存 worker 用时约 201 秒，按样本数线性外推不可靠。本轮另行记录全量缓存耗时、训练步时、显存和主机内存，不预先承诺节省比例或总耗时。

**三条边界（不得越过）**

1. **无独立留出集**：285 张全部入训，不能声称泛化；「学会画风」与「记住训练样本」不可分。

**本轮新增的三条限制（与上面三条并列）**

1. **90% 档是「早期饱和」而非「没学到」**：像素上它的三列几乎一样（570→900 仅 12.18，四组最小），但 B 的全局 L2 仍从 3.324 长到 5.225（+57%）；且它在 285 步就已达 vs-Base 28.28，与稠密 285 的 28.58 同量级。不能把「画面变化小」读成「优化没发生」。
2. **基线不同源**：本轮 calibration 的 285 步稠密 B 与 task10 dense285 非逐值复现（0/252 层相同、最大绝对差 8.99e-3、L2 5.2526 vs 5.4986），差异从**首步 grad_norm** 就已出现（0.144279 对 0.143461），指向反向/内核非确定性；而像素对比的 Dense 四列取自 task10 归档，因此「稠密 vs 稀疏」的差异里混入了这层基线差异（只影响掩码阈值附近的坐标）。
3. **仍是 6 组提示 × 2 seed 的定型观察**：无独立留出集、无真人盲评（13 列未做盲评），像素差不是质量排名；90% 更接近 Base、30% 更接近稠密，都不构成「哪个更好」的结论。
