# Knit-Edit 论文与 MOSS-Image LoRI 首轮复核

2026-11-18 · 核对根目录 PDF、LoRI 原论文、训练器实现、Task 6 检查点和 Task 7 采样记录。本次复核使用 CPU 读取既有工件，没有修改训练代码或启动训练与采样。

**Knit-Edit 是 LoRI 思路用于视觉 DiT 的已发表先例。** 它在 FLUX.1 Kontext 上训练多种针织服装编辑适配器，主实验明确报告 rank 8 和稀疏率 0.0。按通常定义，这对应稠密 B。它给出了固定投影、条件设计与多任务合并的视觉证据，对 MOSS-Image 的 90% 稀疏风格训练及低显存收益没有直接实测。我们首轮的固定 A、全局幅值掩码、B 清零和紧凑优化器状态都有运行证据。当前最明确的质量问题是实验缺少同配方基线和留出评估。实测掩码有 50.29% 的 B 输出行没有活跃坐标，应优先用稠密 B 对照检验这一容量限制。 [本地 PDF](../../Knit-Edit_A_Unified_Multi-Task_Editing_Framework_f.pdf) · [期刊版 §3.3、§4.1.2](https://doi.org/10.3390/electronics15061208) · [本地首轮报告](2026-11-18-lori-experiment-results.md)

同名概念需要分开读取。`Mᵢ` 在 Eq. (2) 是 B 每个位置的二值掩码，§4.1.2 又以 `Mᵢ = 0.0` 表述稀疏率。按零元素占比的含义，0.0 等价于保留全部坐标。论文未披露非零稀疏率下的掩码选择、校准后重置、随机正交投影的构造方式（例如 QR）、各任务实际是否独立取 A，也未说明融合权重如何求得。正文提到视觉的二维空间特征，公式仍是线性权重更新。二维定位由图像条件和色框提供，论文未给出额外的二维投影算子。 [Knit-Edit §3.3–3.5、§4.1.2](https://doi.org/10.3390/electronics15061208)

### 结果能支持什么

- **图像编辑指标随条件和训练时长一起变化。** 表 2 的三个配置按顺序加入 EditLoRI 和色框。区域外 MSE 为 1450 → 1168 → 991，FID 为 20.49 → 9.82 → 5.90。缺少“普通 LoRA + 色框”一格，因此只能估计该顺序下的变化，无法独立估计两个组件的交互。图 8 在 1,000–3,000 步的 FID 从 14.34 降到 5.90，随后 CLIP Image 在约 0.965 附近。表 4 的 rank 8 是作者综合选择，rank 32 的 MSE 991、FID 5.90 仍略优于 rank 8 的 1021、5.94。见第 11–13 页 §4.3.1、§4.3.3–4.3.4。 [论文](https://doi.org/10.3390/electronics15061208)
- **合并后的 EditLoRI 多数指标优于文中的 Merged LoRA。** 表 3 的加图案、试衣、移除物件 FID 分别为 5.94 / 28.76 / 3.01，对照为 35.95 / 51.83 / 27.40。加图案和试衣的 PSNR 却分别低于对照（20.79 < 22.45，13.70 < 15.16），移除物件的 CLIP-IQA 也低于对照（0.56 < 0.57），与表注的全指标优胜表述存在出入。试衣与专用模型相比也有胜负，见表 1。见第 9–12 页 §4.2、§4.3.2。 [论文](https://doi.org/10.3390/electronics15061208)
- **层更新绝对内积下降，跨任务正交程度仍待验证。** 论文报平均绝对内积 0.0524 对 0.0847，平均 Frobenius 更新范数 6.36 对 8.04。绝对内积同时受方向与范数影响，缩小更新幅度本身就能使其下降。第 15 页把任务子空间的余弦验证列为后续工作。还需比较相同任务在单独启用和融合时的质量差，才能把几何量与功能干扰联系起来。见第 13–15 页 §4.3.5–4.3.6、§5。 [论文](https://doi.org/10.3390/electronics15061208)

若令 `Cᵢ = Bᵢ ⊙ Mᵢ`，则 `⟨ΔWᵢ, ΔWⱼ⟩F = tr(Cᵢ Aᵢ Aⱼᵀ Cⱼᵀ)`。任务共用行正交 A 时，`AAᵀ = I`，公式变成 `⟨Cᵢ, Cⱼ⟩F`。同一 A 加上各自的稀疏掩码，仍可能在相同坐标上产生重叠。互斥坐标在这个假设下足以让 Frobenius 内积为零，但任务的输入子空间仍是共享的。若要从 A 的构造保证线性更新的 Frobenius 正交，一个充分条件是 `Aᵢ Aⱼᵀ = 0`，仅对每个 A 分别做行正交还缺少这项跨任务约束。原版 LoRI §2.2 通过各任务独立的随机 A，在 `r ≪ d_in` 和其他条件下给出渐近近似正交。算法 1 在同一任务的校准和稀疏训练间复用 A。 [Knit-Edit §3.3、图 3](https://doi.org/10.3390/electronics15061208) · [LoRI 原论文 §2.2、附录 B–C](https://arxiv.org/html/2504.07448v2)

## 当前 MOSS-Image LoRI 可能卡在哪里

**已核对的算法路径。** 原版 LoRI 写 `A(B ⊙ M)`，以行向量右乘权重。PyTorch `Linear` 以 `[out,in]` 储存权重，本地对应 `ΔW = (α/r)(B ⊙ M)A`。`LoRIModule` 用 `U[−√(3/d_in), +√(3/d_in)]` 初始化 A 并注册为冻结缓冲区，校准 B 从零开始。`make_sparse_init` 合并所有目标层的 `abs(B)`，取一个分位阈值，保留 `>=`（含并列），复制 A/alpha，给活跃索引新建零值 B。历史工件证实 A/alpha 相同、B 全零且稀疏阶段在新进程里初始化优化器。最终 252 个 B 向量都有更新，AdamW 一阶、二阶矩各有 1,066,599 个元素。暂未发现可解释首轮视觉结果的核心公式或阶段切换缺陷。前向临时重建稠密 B，现有资源实测尚缺同配置 LoRA/稠密 B 对照。 [原论文 §2.1、附录 B](https://arxiv.org/html/2504.07448v2) · [作者掩码代码](https://github.com/juzhengz/LoRI/blob/main/src/extract_mask.py) · [本地数学模块](../../KohakuMossTrainer/src/kohakumoss/adapters/kinds/lori.py) · [本地掩码模块](../../KohakuMossTrainer/src/kohakumoss/adapters/train/lori.py) · [阶段启动检查](../../experiment/task6/session-20261118-a/sparse-ready-check.json) · [最终审计](../../experiment/task6/session-20261118-a/sparse-final-audit.json)

## 优先借鉴的实验设计

1. **先建立三臂训练对照。** 在当前 12 张上做可学性小试，锁定 INT8 主干、`attn-mlp`、rank 8/alpha 16、AdamW、分辨率、数据顺序、噪声/timestep 与有效优化步。比较普通 LoRA、固定 A 的稠密 B、12 步校准后的 90% LoRI。固定 A 两臂使用相同 A，稀疏臂继续从零 B 开始。保留 32/128/256 步中间点，视曲线再延长。若 LoRA 与稠密 B 都弱，先核对数据、训练尺度和有效训练量。若 LoRA 提升而稠密 B 落后，优先检查固定基底或 rank。若稠密 B 提升而稀疏 B 落后，优先检查掩码或坐标预算。记录参数、优化器状态、前向峰值、整阶段显存与步时。相同后续优化步便于质量比较，同时单独记入 LoRI 校准成本。 [首轮参数](../../experiment/task6/session-20261118-a/common.py) · [Knit-Edit 图 8](https://doi.org/10.3390/electronics15061208)
2. **只改校准长度或只改保留比例。** 若 90% LoRI 落后，先从同一连续校准轨迹提取 12/48/96 步的掩码，固定 A、稀疏率和正式训练预算。记录掩码 Jaccard、各 sigma/种子的稳定性、各层密度和零活跃输出行。再固定校准检查点，对比 90% 和 50% 稀疏。同一 rank 下的稀疏率比较有助于定位容量问题。若有提升，再比较 `r=8, s=0.5` 与 `r=16, s=0.75` 这类活跃预算近似相等的设置，同时记录实际 nnz、冻结 A 字节和计算开销。比较更大数据池时，用现有 285 对源数据的只读清单按近重复或同系列分组留出，校准只能看到训练部分。 [LoRI 原论文 §3.5](https://arxiv.org/html/2504.07448v2) · [现有只读数据清单](../../experiment/data/round2-caption-12/inventory.json)
3. **把目标学会和原有能力保留分别量化。** 复用已有的 `VALIDATION` 回调，固定留出图、噪声种子和多档 sigma，保存每档与平均 flow loss。同时按 Knit-Edit 的思路，把视觉评估分成目标风格（线条、色彩、明暗等，与独立风格参考盲评）和内容保留（主体、构图、提示一致性与瑕疵）。在固定采样参数下跨多个图像种子，以 256/512 两档分别比较。对触发词，用
   `（适配器带词得分 − Base 带词得分）−（适配器无词得分 − Base 无词得分）`，避免把 Base 对词串的自然响应算给适配器。编辑任务日后若有配对源图和目标区域，才直接使用区域内编辑成功率与区域外结构/纹理保留指标。 [本地固定噪声验证](../../KohakuMossTrainer/src/kohakumoss/training/callbacks/evaluate.py) · [Knit-Edit §4.1.4、表 2](https://doi.org/10.3390/electronics15061208)
4. **等两个适配器各自达标，再测任务合并。** 对独立任务启用独立 A，另设共用 A 作为实验臂。以 `Σ λᵢΔWᵢ` 或等价的适配器相加做合并，避免分别相加 A、B 后出现交叉项。并列记录每层更新范数、余弦、掩码重叠率、固定任务集的“合并减单独”质量变化；用预定或验证集选择的 λ，再在留出样本上报告退化。真正要做参考图针织编辑时，再借鉴色框和配对数据设计，分别用有框和无框实验核对定位收益。 [Knit-Edit Eq. (3)、图 4、图 9–10](https://doi.org/10.3390/electronics15061208) · [LoRI 原论文 §2.2](https://arxiv.org/html/2504.07448v2)
